1.Overview

OnamDelivery is a hyperlocal flower-delivery marketplace for the Onam season. It connects three sides of a marketplace — customers who order flowers, vendors who sell them, and delivery partners who carry them — under a single company-owner dashboard that keeps the platform operator in full control. Every order carries a guaranteed per-order profit for the platform, and delivery partners are paid per kilometre at a rate that always beats their fuel cost.

The system is edge-first and serverless: the entire backend is one Cloudflare Worker talking to a serverless SQLite database (D1), with no self-hosted servers, no containers, and no per-instance state.

Customers

Flutter

Browse, order, pay COD, live-track the partner, and rate the vendor.

Vendors

Web console

List stock, edit prices, toggle open & own-delivery, see the order queue.

Partners

Flutter · Android

Go online, accept orders, navigate with GPS, deliver with an OTP, earn per km.

Owner

Web dashboard

Edit any vendor’s stock/price, analytics, settlements, approvals, live ops map.

Key design goals — four role-isolated surfaces sharing one API · COD-first payments · vendor “zero-hassle” console · guaranteed platform margin · Indian DPDP Act 2023 compliance.

2.High-Level Architecture

Three client surfaces talk to a single stateless Worker API over HTTPS/JSON. The Worker is the only thing that reads or writes the database; clients never touch D1 directly.

5.Authentication & Authorization

All four roles authenticate with phone + one-time password, then receive a JWT (HS256, 30-day expiry) carrying a role claim and the actor’s id in sub. Consent (DPDP Act 2023) is mandatory and recorded on login.

RoleJWT claimLogin endpointAccess
Customersub = user id/api/auth/*Own orders, reviews, tracking, erasure.
Partnerrole = "partner"/api/partner/*Own profile, order discovery/claim/fulfilment, earnings.
Vendorrole = "vendor"/api/vendor/*Own catalog (price/stock), own orders, shop toggles.
Ownerrole = "owner"/api/owner/*Everything: any vendor’s catalog, analytics, settlements, approvals, settings.

Role isolation is enforced server-side by four guards — requireAuth, requirePartner, requireVendor, requireOwner — each rejecting tokens with the wrong role. A vendor can edit only their own products (ownership check returns 404 otherwise); a customer or partner token is rejected with 401 on any admin endpoint.

6.Economics & Pricing Engine

Every order’s money is computed in lib/pricing.ts from rates stored in the settings table — so the owner can retune the whole platform without a redeploy. Rates derive from the fuel constraint: ₹116/litre ÷ 20 km/litre = ₹5.80/km, so partner pay must always clear that.

SettingDefaultMeaning
platform_fee₹20Flat developer profit on every order (guaranteed).
delivery_base_fee₹40Customer delivery base charge.
delivery_rate_per_km₹15Customer delivery charge per km.
partner_base_pay₹30Partner base earnings.
partner_rate_per_km₹10Partner earnings per km (beats ₹5.80 fuel → ≈₹4.2/km net).
fuel_cost_per_km₹5.80Reference for the above invariant.

Per order (platform delivery): total = subtotal + delivery_fee + platform_fee; the vendor keeps subtotal, the partner earns delivery_pay, and the platform keeps platform_fee + (delivery_fee − delivery_pay). On vendor self-delivery, delivery_pay = 0 but the ₹20 platform fee still applies.

7.Order Lifecycle & Data Flow

An order moves through a linear fulfilment ladder, with a handover OTP at the final step.

7.1 End-to-end flow

  1. Browse — the customer app fetches vendors (distance/radius-filtered) and products from the Worker.
  2. Order — POST /api/orders validates stock, computes the ₹ breakdown, decrements stock, and stores the handover OTP.
  3. Assign — a partner sees the order in /api/partner/orders/available and atomically claims it.
  4. Track — the partner streams GPS to /api/partner/me; the customer polls /api/orders/:id/track (5 s) to watch the partner move.
  5. Deliver — the partner enters the customer’s OTP to complete the delivery.
  6. Review — the customer rates the order; the rating rolls into the vendor’s average.
  7. Observe — the owner dashboard reflects revenue, platform profit, partner earnings, and per-vendor settlements in real time.

9.Compliance (Indian regulations)

DPDP Act 2023

  • Explicit, recorded consent — every login (customer, partner, vendor, owner) requires a consent checkbox; the API records consented_at + consent_version and refuses (400) without it.
  • Right to erasure — DELETE /api/me anonymizes the user’s personal data and deletes addresses.
  • Grievance officer — published in /api/settings and shown in the customer app.
  • Purpose limitation — partner/vendor consent text states exactly what data is processed (name, phone, location) and why.

Consumer Protection (E-Commerce) Rules 2020

  • Transparent pricing — item price, delivery fee, and the ₹20 platform fee are itemized at checkout and in the order history.
  • COD-first — cash on delivery is the default payment method; UPI is an optional extra.
